Stan i historia


Projekty developmentu




Wybierz repozytorium z ~/github/. Otwieraj foldery, aby dotrzeć do projektu.


  



 







Obsługiwane są istniejące repozytoria Git i naprawy plików Python. Dodanie tworzy prywatną kopię; development nigdy nie zapisuje do projektu PC.







 


Zarządzanie projektem i ticketami: w terminalu ./gitive project open. Wybierz projekt, dodaj ticket, uruchom go i sprawdź procesy. ./gitive menu 4 otwiera ten sam wybór.
DigitalTwin = pulpit noVNC + workspaces projektów + prywatne pliki + dostęp GitHub. Rejestracja kopii kodu nie oznacza jeszcze sklonowania całego runtime PC.
Dodawanie: ./gitive project add nazwa ścieżka --goal "cel" --test "python3 -m unittest discover -s tests"
Praca: ./gitive project run nazwa
Kopia środowiska PC → noVNC
PC: tylko odczyt. noVNC: osobne pliki i profile. Resync działa wyłącznie PC → kopia.


Snapshoty projektów są szyfrowane. Profile LLM, IDE i shella są opcjonalnie kopiowane do osobnego katalogu offline. Działające procesy nie są przenoszone. Przed operacją zatrzymaj pętlę Gitive.

 

Inwentaryzacja i dostępne kopie


1. Snapshot projektu i wybranych sesji







Przed kopiowaniem profili zamknij używające ich aplikacje. Kopia może zawierać dane logowania; nie nadpisuje aktywnych profili.


2. Odtwórz kopię


3. Synchronizuj PC → kopia
Własne zmiany w kopii blokują zapis. Przed zastosowaniem powstaje kopia poprzedniego katalogu.


4. Otwórz kopię archiwalną w noVNC
Dla projektu z własnym kontenerem użyj skrótu „Gitive nazwa-projektu” na pulpicie noVNC albo na PC: ./gitive twin terminal nazwa-projektu. Ten terminal zachowuje użytkownika, HOME i ścieżkę z PC.


Profile przeglądarek — istniejący Hub
Dotyczy konta softreck w hubie. Operacja może zatrzymać jego pulpit i terminale; restore zastępuje profile zapisanym stanem. Hub zarządza własnym magazynem snapshotów.
